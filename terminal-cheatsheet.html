Terminal-Spickzettel

Die Befehle, die wir im Alltag wirklich brauchen — Dateien verwalten und gemeinsam mit Git arbeiten. Kein Fachjargon, keine Überraschungen. Einfach nachschlagen, wenn du unsicher bist.

01

Navigation — wo bin ich, wo will ich hin

BefehlBedeutung
pwd Zeigt den Ordner, in dem du dich gerade befindest („print working directory“).
ls ls -la Listet den Inhalt des aktuellen Ordners auf. Mit -la siehst du auch versteckte Dateien (die mit einem Punkt beginnen) und Details wie Größe und Rechte.
cd cd src/components Wechselt den Ordner („change directory“). Ohne Angabe eines Ziels springt cd zurück in dein Home-Verzeichnis.
.. cd .. Steht für den übergeordneten Ordner (eine Ebene nach oben). cd ../.. geht zwei Ebenen hoch.
. ./script.sh Steht für den aktuellen Ordner. ./ vor einem Dateinamen sagt dem Terminal „führe diese Datei genau hier aus“ — wichtig bei ausführbaren Skripten.
☺ Faustregel: Wenn du dich verirrst, hilft immer pwd gefolgt von ls — erst schauen, wo du bist, dann was um dich herum liegt.
02

Anlegen — Dateien und Ordner erstellen

BefehlBedeutung
touch touch notizen.txt Erstellt eine neue, leere Datei. Existiert die Datei schon, passiert nichts Schlimmes — nur ihr „zuletzt geändert“-Datum wird aktualisiert.
mkdir mkdir -p projekte/kunde-a Erstellt einen neuen Ordner („make directory“). Mit -p legt es auch alle fehlenden übergeordneten Ordner gleich mit an, ohne Fehlermeldung.
03

Verschieben & umbenennen

BefehlBedeutung
mv mv entwurf.jpg archiv/ Verschiebt eine Datei oder einen Ordner an einen anderen Ort („move“). Es gibt keinen separaten Befehl mvdir — mv funktioniert für Dateien und Ordner gleichermaßen.
mv mv alt.txt neu.txt Wird mv innerhalb desselben Ordners verwendet, benennt es die Datei oder den Ordner einfach um.
04

Kopieren

BefehlBedeutung
cp cp entwurf.jpg archiv/ Kopiert eine Datei an einen anderen Ort oder unter einem neuen Namen („copy“). Anders als mv bleibt das Original erhalten.
cp -r cp -r projekte/kunde-a projekte/kunde-a-kopie Kopiert einen ganzen Ordner samt Inhalt („recursive“). Ohne -r meldet cp bei Ordnern einen Fehler — genau wie bei rm weiter unten.
05

Löschen

BefehlBedeutung
rm rm entwurf.jpg Löscht eine einzelne Datei unwiderruflich („remove“) — landet nicht im Papierkorb.
rmdir rmdir alter-ordner Löscht einen Ordner — aber nur, wenn er komplett leer ist.
rm -r rm -r alter-ordner Löscht einen Ordner samt allem Inhalt („recursive“) — auch wenn er nicht leer ist.
⚠ Vorsicht: Gelöschtes über rm ist weg — es gibt keinen Papierkorb und kein „Rückgängig“. Im Zweifel erst mit ls prüfen, was du löschst.
06

Git-Workflow im Team

So läuft ein normaler Arbeitstag ab, wenn wir beide am selben Repository arbeiten — immer in dieser Reihenfolge.

  1. git pull
    Holt die neuesten Änderungen der anderen Person, bevor du anfängst zu arbeiten. So vermeidest du Konflikte.
  2. … jetzt deine Änderungen machen, Dateien bearbeiten, speichern …
  3. git status
    Zeigt dir, welche Dateien du geändert, hinzugefügt oder gelöscht hast. Guter Zwischencheck, bevor du weitermachst.
  4. git add .
    Merkt alle geänderten Dateien im aktuellen Ordner für den nächsten Commit vor („staging“). Der Punkt steht für „alles hier“.
  5. git commit -m "Kurze Beschreibung"
    Speichert die vorgemerkten Änderungen dauerhaft im Verlauf — mit einer kurzen Nachricht, was du gemacht hast.
  6. git push
    Lädt deine Commits zum gemeinsamen Repository hoch, damit die andere Person sie auch sehen kann.
☺ Merksatz: Erst pull, dann arbeiten, dann add → commit → push. Wenn git push mal ablehnt, meist hilft ein weiteres git pull davor — die andere Person war schneller.
